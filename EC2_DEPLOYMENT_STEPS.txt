│                      STEP 2: AWS SECURITY GROUP                        │
│                        (5 minutes)                                     │
└─────────────────────────────────────────────────────────────────────────┘

Go to AWS Console:

    1. EC2 → Security Groups
    2. Select your EC2 instance's security group
    3. Click "Edit inbound rules"
    4. Add these rules:

       Rule 1: SSH
       ├─ Type: SSH
       ├─ Protocol: TCP
       ├─ Port: 22
       └─ Source: YOUR-IP-ADDRESS (your home/office IP)

       Rule 2: Application
       ├─ Type: Custom TCP
       ├─ Port: 8000
       └─ Source: 0.0.0.0/0 (anywhere)

       Rule 3 (Optional - if using Nginx):
       ├─ Type: HTTP
       ├─ Protocol: TCP
       ├─ Port: 80
       └─ Source: 0.0.0.0/0 (anywhere)

    5. Click "Save rules"

✓ Your EC2 instance can now receive connections

================================================================================
                              TROUBLESHOOTING
================================================================================

PROBLEM: "Connection refused" or "Cannot access from browser"
───────────────────────────────────────────────────────────────────────────
Solution:
  1. Check security group allows port 8000
  2. Verify service is running: sudo systemctl status qvc-bot.service
  3. Check if port is listening: sudo lsof -i :8000
  4. View logs: sudo journalctl -u qvc-bot.service -n 50

PROBLEM: "Service won't start"
───────────────────────────────────────────────────────────────────────────
Solution:
  1. Check logs: sudo journalctl -u qvc-bot.service -n 100
  2. Test manually: cd /home/ubuntu/apps/qvc-v2 && python web_server.py
  3. Check Python dependencies: pip install -r requirements.txt
  4. Check .env file exists: cat /home/ubuntu/apps/qvc-v2/.env

PROBLEM: "Database connection error"
───────────────────────────────────────────────────────────────────────────
Solution:
  1. Verify MONGODB_URI in .env is correct
  2. Test connection if local: mongo
  3. Test connection if Atlas: telnet cluster.mongodb.net 27017
  4. Check credentials in connection string

PROBLEM: "Frontend loads but no API responses"
───────────────────────────────────────────────────────────────────────────
Solution:
  1. Check CORS is enabled (should be by default)
  2. Check browser console for errors (F12 → Console tab)
  3. Check service is running and responding: curl http://localhost:8000/health
  4. Restart service: sudo systemctl restart qvc-bot.service

PROBLEM: "Out of memory or slow performance"
───────────────────────────────────────────────────────────────────────────
Solution:
  1. Check instance type has enough RAM (4GB minimum, 8GB recommended)
  2. Monitor: top or htop
  3. For parallel browser sessions: Increase EC2 instance size
  4. Monitor logs for memory errors


================================================================================
                           OPTIONAL SETUP: NGINX
================================================================================

If you want to run the app on port 80 (standard HTTP) instead of 8000:

    # Install Nginx (if not done in setup_ec2.sh)
    sudo apt install nginx

    # Copy configuration
    sudo cp /home/ubuntu/apps/qvc-v2/nginx.conf \
            /etc/nginx/sites-available/qvc-bot

    # Remove default site
    sudo rm /etc/nginx/sites-enabled/default

    # Enable our site
    sudo ln -s /etc/nginx/sites-available/qvc-bot \
               /etc/nginx/sites-enabled/

    # Test configuration
    sudo nginx -t

    # Restart Nginx
    sudo systemctl restart nginx

    # Now access at: http://YOUR-EC2-IP (without :8000)
